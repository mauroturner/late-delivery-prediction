Diseño del tablero de Power BI: pedidos que van a llegar tarde, antes de que lleguen

Guía para armar el informe en Power BI Desktop a partir de los archivos Parquet de outputs/powerbi: modelo, relaciones, consultas, medidas y las cinco páginas con sus visuales ubicados. Las vistas previas usan los números reales de esos archivos; las celdas con menos de 20 pedidos se ocultan.

Cómo armarlo en Power BI Desktop

  1. Instale Power BI Desktop (gratuito, solo para Windows) y abra un informe en blanco.
  2. Cree un parámetro de texto llamado CarpetaSalidas con la ruta de la carpeta outputs\powerbi de este proyecto.
  3. Cree una consulta por tabla (20) con el código de la sección «Power Query». Cada consulta carga un archivo Parquet; deje el nombre de la consulta igual al de la tabla.
  4. En la vista de modelo, cree las 9 relaciones de la tabla «Relaciones»: cardinalidad uno a varios (1:*), dirección del filtro única (de la dimensión al hecho), todas activas. No cree relaciones bidireccionales ni inactivas; dim_as_of, dim_model y los hechos de la evaluación no tienen relaciones.
  5. Marque dim_date como tabla de fechas con la columna date.
  6. Ordene month_name_es por month, weekday_es por weekday, year_month_label por month_key, mode_es por sort_order y as_of_label por as_of_key. Oculte las columnas de clave de los hechos.
  7. Cree una tabla vacía llamada _Medidas («Especificar datos» sin filas) y agregue en ella las medidas de la sección «Medidas DAX», con su formato.
  8. Cree las 5 páginas a escala 16:9 (1280 × 720 px) y ubique cada visual según la grilla de 12 columnas de la sección «Las cinco páginas».
  9. Guarde el informe como .pbix. Cuando corra el flujo, vuelva a cargar con «Actualizar»: las consultas leen los mismos archivos.
La conexión Parquet.Document es la que usa Power BI Desktop para leer archivos Parquet; si su versión no la ofrece, use «Obtener datos» con el conector Parquet y apunte a los mismos archivos.
Qué se probó y qué no. Las pruebas del proyecto comprueban que los archivos cumplen el modelo (claves únicas, claves foráneas en su dimensión, relaciones de uno a varios con filtro único) y que cada columna y cada medida que nombra el DAX existe. Ninguna medida se ejecutó: no hay un motor de DAX en el equipo que generó este documento. La primera vez que arme el informe, compare unas pocas cifras con las vistas previas de abajo, que salen de los mismos archivos. Pendiente de verificar: que Alertas abiertas a la fecha respete los segmentadores de modo y mercado con el FILTER sobre fact_order; si no los respeta, la alternativa es KEEPFILTERS.
Los costos son supuestos. El umbral de alerta se eligió con costos declarados (una alerta, un retraso y cuánto de él evita la alerta); los datos no traen costos. La tarjeta «Costos supuestos» de la página 1 los muestra junto al umbral.

El modelo en estrella

10 dimensiones y 10 hechos. dim_as_of es una tabla de parámetro: elige la fecha de cálculo de las alertas abiertas. dim_model y los hechos de la evaluación (fact_method_metrics, fact_evaluation_summary, fact_roc, fact_calibration, fact_cost_sensitivity, fact_leakage, fact_importance) no tienen relaciones: cada uno alimenta sus propios visuales. La clave del pedido es el número de pedido de la fuente, que no identifica a ninguna persona; no hay ninguna columna de cliente en el modelo.

Medidas DAX

Todas van en la tabla _Medidas. Los nombres de las medidas y los textos están en español; las tablas y las columnas, en inglés.

Fecha de cálculo elegida

La fecha de cálculo del segmentador o, si no se eligió ninguna, la de la última corrida terminada bien. Las alertas abiertas la usan. Formato: yyyy-mm-dd.

Fecha de cálculo elegida =
IF ( ISFILTERED ( dim_as_of[as_of_key] ),
    SELECTEDVALUE ( dim_as_of[as_of_date] ),
    CALCULATE ( MAX ( dim_pipeline_run[as_of_date] ), dim_pipeline_run[status] = "ok" ) )

Pedidos

Pedidos de las entregas cargadas, con o sin puntaje. Formato: #,0.

Pedidos =
COUNTROWS ( fact_order )

Pedidos puntuados

Pedidos con un riesgo calculado al crearse; los del lanzamiento no se puntúan. Formato: #,0.

Pedidos puntuados =
CALCULATE ( COUNTROWS ( fact_order ), NOT ISBLANK ( fact_order[risk] ) )

Alertas

Pedidos cuyo riesgo alcanzó el umbral cuando se crearon. Formato: #,0.

Alertas =
CALCULATE ( COUNTROWS ( fact_order ), fact_order[is_alert] = TRUE () )

Alertado (%)

Parte de los pedidos puntuados que quedó con alerta. Usa: [Alertas], [Pedidos puntuados]. Formato: 0.0%.

Alertado (%) =
DIVIDE ( [Alertas], [Pedidos puntuados] )

Riesgo medio

Probabilidad media de llegar tarde de los pedidos puntuados. Formato: 0.0%.

Riesgo medio =
AVERAGE ( fact_order[risk] )

Retrasos esperados

Pedidos que el modelo esperaba que llegaran tarde: la suma de los riesgos. Formato: 0.0.

Retrasos esperados =
SUM ( fact_order[risk] )

Alertas abiertas a la fecha

Alertas emitidas hasta la fecha elegida cuyo resultado todavía no se conocía ese día. Usa: [Alertas], [Fecha de cálculo elegida]. Formato: #,0.

Alertas abiertas a la fecha =
VAR d = [Fecha de cálculo elegida]
RETURN CALCULATE ( [Alertas], fact_order[scored_as_of_date] <= d,
    FILTER ( fact_order, ISBLANK ( fact_order[outcome_known_date] ) || fact_order[outcome_known_date] > d ) )

Pedidos cerrados

Pedidos con resultado conocido que no se cancelaron. Formato: #,0.

Pedidos cerrados =
CALCULATE ( COUNTROWS ( fact_order ), fact_order[outcome_status] = "closed" )

Pedidos tarde

Pedidos cerrados cuyos días reales superan a los programados. Formato: #,0.

Pedidos tarde =
CALCULATE ( COUNTROWS ( fact_order ), fact_order[is_late] = TRUE () )

Tasa de retraso observada

Parte de los pedidos cerrados que llegó tarde. Usa: [Pedidos cerrados], [Pedidos tarde]. Formato: 0.0%.

Tasa de retraso observada =
DIVIDE ( [Pedidos tarde], [Pedidos cerrados] )

Alertas cerradas

Alertas sobre pedidos que ya tienen resultado. Usa: [Alertas]. Formato: #,0.

Alertas cerradas =
CALCULATE ( [Alertas], fact_order[outcome_status] = "closed" )

Alertas que llegaron tarde

Alertas sobre pedidos que llegaron tarde: las que acertaron. Usa: [Alertas]. Formato: #,0.

Alertas que llegaron tarde =
CALCULATE ( [Alertas], fact_order[is_late] = TRUE () )

Tarde sin alerta

Pedidos puntuados que llegaron tarde sin que se los marcara. Usa: [Pedidos tarde]. Formato: #,0.

Tarde sin alerta =
CALCULATE ( [Pedidos tarde], fact_order[is_alert] = FALSE () )

Precisión de las alertas

De las alertas cerradas, parte que llegó tarde. Usa: [Alertas cerradas], [Alertas que llegaron tarde]. Formato: 0.0%.

Precisión de las alertas =
DIVIDE ( [Alertas que llegaron tarde], [Alertas cerradas] )

Recall de las alertas

De los pedidos puntuados que llegaron tarde, parte que tenía alerta. Usa: [Alertas que llegaron tarde], [Tarde sin alerta]. Formato: 0.0%.

Recall de las alertas =
DIVIDE ( [Alertas que llegaron tarde], [Alertas que llegaron tarde] + [Tarde sin alerta] )

Umbral

Probabilidad desde la cual un pedido queda con alerta; se eligió en V2 por beneficio neto. Formato: 0.00.

Umbral =
SELECTEDVALUE ( dim_model[threshold] )

Costos supuestos

Los costos con que se eligió el umbral, dichos como supuestos: los datos no traen costos. Formato: @.

Costos supuestos =
"Costos supuestos, no medidos: alerta " & FORMAT ( SELECTEDVALUE ( dim_model[alert_cost] ), "0.0" ) & " u., retraso " & FORMAT ( SELECTEDVALUE ( dim_model[late_cost] ), "0.0" ) & " u., efecto " & FORMAT ( SELECTEDVALUE ( dim_model[effect] ), "0.00" )

Beneficio neto estimado (u.)

Beneficio de las alertas cerradas con los costos supuestos, en unidades de costo genéricas. Usa: [Alertas cerradas], [Alertas que llegaron tarde]. Formato: 0.0.

Beneficio neto estimado (u.) =
[Alertas que llegaron tarde] * SELECTEDVALUE ( dim_model[late_cost] ) * SELECTEDVALUE ( dim_model[effect] )
    - [Alertas cerradas] * SELECTEDVALUE ( dim_model[alert_cost] )

Precisión mensual

Precisión de las alertas cerradas, por mes del pedido. Formato: 0.0%.

Precisión mensual =
DIVIDE ( SUM ( fact_tracking_monthly[alerts_late] ), SUM ( fact_tracking_monthly[closed_alerts] ) )

Recall mensual

Recall de las alertas cerradas, por mes del pedido. Formato: 0.0%.

Recall mensual =
DIVIDE ( SUM ( fact_tracking_monthly[alerts_late] ),
    SUM ( fact_tracking_monthly[alerts_late] ) + SUM ( fact_tracking_monthly[late_missed] ) )

Retrasos esperados en el mes

Suma del riesgo de los pedidos cerrados del mes. Formato: 0.0.

Retrasos esperados en el mes =
SUM ( fact_tracking_monthly[late_expected] )

Retrasos observados en el mes

Pedidos cerrados del mes que llegaron tarde. Formato: #,0.

Retrasos observados en el mes =
SUM ( fact_tracking_monthly[late_closed] )

Alertado mensual (%)

Parte de los pedidos puntuados del mes que quedó con alerta. Formato: 0.0%.

Alertado mensual (%) =
DIVIDE ( SUM ( fact_tracking_monthly[alerts] ), SUM ( fact_tracking_monthly[orders_scored] ) )

Días reales medios

Días reales de envío de los pedidos cerrados. Formato: 0.0.

Días reales medios =
AVERAGE ( fact_order[real_days] )

Días programados

Días programados que fija la fuente para el modo de envío. Formato: 0.0.

Días programados =
AVERAGE ( dim_shipping_mode[scheduled_days] )

Veredicto

El veredicto del criterio elegido, con su número; dice «supera» o «no supera». Formato: @.

Veredicto =
SELECTEDVALUE ( fact_evaluation_summary[verdict_es] )

Última fecha de cálculo

La fecha de cálculo de la última corrida terminada bien. Formato: yyyy-mm-dd.

Última fecha de cálculo =
CALCULATE ( MAX ( dim_pipeline_run[as_of_date] ), dim_pipeline_run[status] = "ok" )

Estado de la última corrida

El estado (running, ok, failed…) de la corrida con la fecha de cálculo más reciente. Formato: @.

Estado de la última corrida =
VAR k = CALCULATE ( MAX ( dim_pipeline_run[as_of_key] ), REMOVEFILTERS ( dim_pipeline_run ) )
RETURN CALCULATE ( SELECTEDVALUE ( dim_pipeline_run[status] ), REMOVEFILTERS ( dim_pipeline_run ), dim_pipeline_run[as_of_key] = k )

Reglas bloqueantes fallidas

Reglas bloqueantes que fallaron en las corridas elegidas. Formato: #,0.

Reglas bloqueantes fallidas =
CALCULATE ( COUNTROWS ( fact_validation ), fact_validation[severity] = "bloqueante", fact_validation[status] = "falla" )

Pedidos cancelados

Pedidos que se cancelaron después de crearse; están fuera de la tarea. Formato: #,0.

Pedidos cancelados =
CALCULATE ( COUNTROWS ( fact_order ), fact_order[outcome_status] = "cancelled" )

Las cinco páginas

Cada página es un lienzo de 1280 × 720 px (16:9) sobre una grilla de 12 columnas por 9 filas. La posición de cada visual está en celdas: x e y desde la esquina superior izquierda. Las vistas previas de la página 4 muestran la prueba si ya se evaluó y, si no, la validación (V2), rotulada.
